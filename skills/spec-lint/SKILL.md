# spec-lint — 명세서 핸드오프 게이트

역할 분담: **Claude = 컨트롤러/검수자, GLM-4.7-Flash(로컬) = 1차 추출 오퍼레이터.**
목적: 클로드코드가 "애매한 명세 받고 멋대로 추측"하는 실패를 핸드오프 전에 차단.

## 실행 절차 (Claude가 수행)

1. 사용자가 던진 명세를 임시 파일 `_spec_input.txt`로 저장(UTF-8).
2. 로컬 GLM 호출:
   ```
   python3 ~/.claude/skills/spec-lint/scripts/spec_lint.py _spec_input.txt
   ```
   - ollama가 안 떠 있으면 `ollama serve` 먼저 안내(보통 자동 실행됨).
   - GLM은 19GB 점유, 첫 호출 시 로딩에 수~십초 걸릴 수 있음.
3. **Claude가 GLM 출력을 검수한다(채찍질 단계):**
   - 오탐(실제론 명세에 있는데 누락이라 한 것) 제거.
   - GLM이 놓친 결함 보강(특히 도메인 지식 필요한 것 — GLM은 일반 린트만, 기계설계 같은 전문 누락은 Claude가 추가).
   - 치명도 재정렬.
4. **정제 리포트 출력**: GLM 원시결과가 아니라 Claude가 검수·보강한 최종본을 표로 제시. 각 결함에 "구현자가 물어야 할 질문" 포함.
5. 마지막에 BLUF: 종합판정(구현가능/조건부/불가) + 클로드코드로 넘기기 전 반드시 메워야 할 항목 1~3개.

## 원칙
- GLM 출력을 그대로 전달하지 마라. Claude가 한 번 거른 것만 사용자에게 준다(이게 이 스킬의 핵심 가치).
- 명세에 없는 사실 날조 금지(GLM·Claude 양쪽 다). 불확실은 "확인필요"로.
- 토큰 절약: 명세 본문 재인용 최소화, 결함 표 위주.
